# <u>Introduction</u>
Distinguish between:
- **Artificial Intelligence:** computer behaviour is programmed by hand
- **Machine Learning:** computer programmatically learns from data, but features, hyperparameters, etc. determined by hand
	- **Deep Learning:** computer programmatically learns from data and determines the features, etc. programmatically as well

Machine learning can be broken down into three modular components:
1. A model architecture which specifies the form of the relationship between inputs and outputs; an example is representing the prediction as a linear combination of features.
2. A loss (or cost) function which measures how well the model fits the data by assigning a numerical penalty to prediction errors; an example is the squared-error for regression.
3. An optimization algorithm which determines how the model’s parameters are learned in order to reduce the loss; gradient descent is an example
This modular approach is useful because it clearly distinguishes three parts: what we assume about the data, how we measure errors, and how we learn from the data; by keeping some components fixed and changing others, we can construct many different machine learning algorithms within a single framework
# <u>1: Supervised Learning</u>
## <u>Supervised Learning</u>
The objective of **supervised learning** is to **learn** a function that maps an input to an output based on a **training set**, which will then be used to perform predictions in a **test set**
- The function that maps inputs to outputs is termed a **predictor**, a **hypothesis**, or a **model**
- **Training Set:** a set of **labeled** input-output pairs, used in the learning process itself
- **Test Set:** a set of **unlabeled** inputs, the outputs of which are known and used to asses accuracy
Other forms of machine learning differ:
- Supervised learning always uses data with **known ground truth labels** to predict labels for other inputs
- **Reinforcement learning** (RL) receives a reward signal and tries to maximize said reward signal; this may or may not involve ground truth labels
- **Unsupervised learning** attempts to find patterns in data without known ground truth labels

Although input formats can differ, we can **always** represent an input using $D$ **numerical features** that we combine into an **input vector** $\mathbf{x} \in \mathbb{R}^D$:
- Each component $x_{i}\in \mathbb{R}$ (where $i \in[1,D]$) in $\mathbf{x}$ is a **feature**, representing some characteristic of the input
	- Representing inputs in such a way allows use to reason about the inputs and the learning process **geometrically** by using linear algebra, and affords us a lot of flexibility in terms of possible inputs (ex. representing images as vectors of pixel intensities, etc.)
- To differentiate between different input vectors we use a bracketed superscript, ex. the $i^{\text{th}}$ feature of the $k^{\text{th}}$ input is $x_{i}^{(k)}$
- The **target** output $t\in \mathbb{R}$ is the label that our function aims to correctly map to, and the **prediction** output $y\in \mathbb{R}$ is the output actually generated by the function, ie. $y=f(\mathbf{x})$
	- A training set of size $N$ then contains pairs of inputs and outputs, ex. $\{(\mathbf{x}^{(1)},t^{(1)}), (\mathbf{x}^{(2)},t^{(2)}), \dots, (\mathbf{x}^{(N)},t^{(N)}) \}$
- Supervised learning tasks can be partitioned into:
	- **Classification:** the target $t$ is **discrete**, ie. it is a value in a finite set of size $C$; $t\in \{ 1,\dots,C \}\subseteq \mathbb{R}$, where the model is a **classifier** (commonly taking the form of a piecewise function)
	- **Regression:** the target $t$ is **continuous**, ie. $t\in \mathbb{R}$, where the model is a **regressor**
	- **Structured:** the target $t$ is structured (ex. an image, text, etc.)
	- Note, the kind of task is determined **solely by the output**; input types can be continuous, discrete, or otherwise for any of type of task
- **Parameter:** a configuration **learned by the model** during training, fitted to optimize some objective
- **Hyperparameter:** a configuration **external to the model**, chosen **before learning**
- A **model family** is a class of models that share the same structure (linear models, decision trees, neural networks, etc.) but differ in their choice of parameters and hyperparameters

**Learning:** the process of determining a model $f:\mathbb{R}^D\to \mathbb{R}$ given a training set, using a learning algorithm
- Learning algorithms generally involve some **optimization** procedure
- For a classifier which is a piecewise function, learning is determining the **decision boundaries** in the input space that split the cases
	- Formally (somewhat), a decision boundary is the set of points in the input space (in the entire possible input space, not just training data) where changing the point by a tiny bit would change the corresponding prediction for the model
		- For models with $2$ or $3$ features, decision boundaries are easy to visualize as lines, planes and other geometric shapes on a plane and in space respectively
**Inference:** using a model to compute a prediction $y=f(\mathbf{x})$

**Evaluation** of a model aims to asses how well it performs and is generally independent of the model family, but not independent of task type; for classifiers we can define and measure **accuracy** as the rate at which the classifier produces correct predictions and **error** as the remainder
$$
\begin{align}
\text{accuracy}&=\frac{\sum^N_{i=1}I(y^{(i)}=t^{(i)})}{N} \\
\text{error}&=1-\text{accuracy}
\end{align}
$$
Consider why these definitions are not sensible for regressors; every inequality is treated equally by the identity function $I$, but in a regression all outputs $t^{(i)},y^{(i)}\in \mathbb{R}$ are continuous so instances of equalities are very unlikely by definition!
- Technically incorrect predictions (by the above definition) could still be close to or far away from (will be formally defined later) the correct outputs, so these predictions should not always be blankly treated as incorrect
- Note, accuracy and error are evaluated over a **specific data set**; the same model may measure differently on even slightly different data sets
Evaluation measures are only useful if we specifically segregate the labelled data for specific parts of the supervised training workflow, namely **split the labeled data** into three parts:
- **Training Set:** used for data exploration, training and learning model parameters, and feature engineering (often trains multiple models, including varying hyperparameters, which in turn may lead to different parameters)
- **Validation Set:** evaluate each model to compare their performance and **choose** the best performing one (based on some accuracy and error evaluations), tune hyperparameters if needed
- **Test Set:** estimate the chosen model's **generalization** by evaluating it on the test set, which has specifically not been used in any way during training or model selection
Formally, supervised learning models make the underlying assumption that labeled data points are **independent and identically distributed**; that each data point can be thought of as being sampled from the same underlying sampling distribution, and that the data points are not correlated
- Given this assumption, partitioning the labeled data into the training, validation and test sets should be as simple as randomly selecting points for each set, however; in practice these assumptions often do not hold:
	- Due to the realities of data collection, independence between all observations is often not satisfied and thus training may overfit to a specific source of data that does not generalize
	- Time series and temporal data cannot simply be partitioned into the above sets randomly because adjacent observations are likely not independent; thus training set data must precede all validation set data, etc.
	- Graph data, if split randomly, may lead to some nodes in the training set which leak information about validation set data, etc.

Data should be representative of what we want a model to be ultimately applied to, but data collection is more difficult and complex than it may seem
- **Feature Engineering:** the process of designing and testing features to use for a machine learning task (on the test set); the choice of features determines the data we need to collect and the geometric structure of the data space, and different choices of features can make patterns easier or harder to discover
- **Synthetic Data and Data Augmentation:** data collection can be expensive and prohibitive, but even without these issues, introducing additional variability on top of real data (small artificial perturbations, inserted noise, etc.) can facilitate training of models that generalize more robustly
## <u>k-Nearest Neighbours</u>
**1st-Nearest-Neighbour Classifier:** for a test point $\mathbf{x}$, calculate the distance to **all** training points, find the closest one $\mathbf{x}^{(C)}=\text{argmin}\text{ distance}(\mathbf{x}^{(i)},\mathbf{x})$ and simply set the prediction to its class ie. $y=f(\mathbf{x})=t^{(C)}$
- There are different definitions of closest, stemming from several options for calculating **distance** between data points $\mathbf{x}^{(a)}$ and $\mathbf{x}^{(b)}$
	- **Euclidean Distance:** also known as $L_{2}$ distance in $d$-dimensional space, $||\mathbf{x}^{(a)}-\mathbf{x}^{(b)}||_{2}=\sqrt{ \sum_{j=1}^d (x^{(a)}_{j}-x^{(b)}_{j})}$
	- **Manhattan Distance:** also known as $L_{1}$ distance in $d$-dimensional space, $||\mathbf{x}^{(a)}-\mathbf{x}^{(b)}||_{1}=\left( \sum_{j=1}^d |x^{(a)}_{j}-x^{(b)}_{j}|\right)$
	- **Cosine Distance:** the angle between two vectors; useful when direction is more important than distance, $\text{cos-dist}(\mathbf{x}^{(a)},\mathbf{x}^{(b)})=1-\frac{\mathbf{x}^{(a)}\cdot \mathbf{x}^{(b)}}{ ||\mathbf{x}^{(a)} ||_{2}\cdot||\mathbf{x}^{(b)} ||_{2}}$
- The closest training point is then found at the index $C$ where $\mathbf{x}^{(C)}$ minimizes our chosen distance measure to the test point $\mathbf{x}$ 
- In practice, measures outside of Euclidean distance and Cosine Similarity are rarely useful; sophistication instead comes from finding or automatically learning good features where simple distance metrics work well

**k-Nearest-Neighbours Classifier:** for a test point $\mathbf{x}$, calculate the distance to **all** training points, take the $k$ closest ones and set the prediction to the **modal** class of these points
- This ameliorates an obvious weakness of $1$NNs; their sensitivity to noise and erroneous training data, in which a single such point alone can cause misclassifications for a significant range of test inputs
	- By definition $1$NNs achieve $100\%$ accuracy on the training data (each point is its own nearest neighbour!); however, they capture noise and idiosyncrasies which **may not generalize** to the data set as a whole and are thus **overfitted** to the training data
- Here $k$ is a hyperparameter; the researcher chooses this configuration during validation, it is not automatically learned by the learning algorithm
	- The issues with $k=1$ are explained above; in the other extreme $k=N$ (where $N$ is the size of the training set) the model will simply always predict the **modal** classification of the entire training set regardless of the input, and is thus **underfitted** to the training data and the data as a whole
	- In general lower $k$ leads to complex and sharply varying decision boundaries that capture small local deviations, while larger $k$ smooths the boundary out but may miss local structures
	- Under some theoretical assumptions we can get bounds on an optimal figure as $k<\sqrt{ N }$, but again in practice $k$ is selected during validation
- Overall:
	- Lower $k$: complex decision boundary, captures fine-grained detail of training set, sensitive to noise
	- Higher $k$: smooth decision boundary, misses local structures of training set, stable predictions

**Decision Boundary:** a subset of the data space that separates different classes; the set of points in the input space where the classifier output is ambiguous and perturbing the point by a tiny amount would change its corresponding predicted output
- **Voronoi Diagrams** segment the plane around each data point with lines that are exactly equidistant from neighbouring points
	- For a $1$NN model with **any** number of classes and:
		- $1$ feature; the Voronoi regions are simply intervals of values of the feature
		- $2$ features; the Voronoi regions are regions of $\mathbb{R}^2$, $3$ features; the Voronoi regions are regions of $\mathbb{R}^3$
		- $> 3$ features; Voronoi diagrams cannot be visualized!
	- To draw a Voronoi region for a given training data point in a $1$NN:
		- Draw the **direct lines** connecting the point to **each** other training data point, then draw the the **perpendicular bisector** to each line, then repeatedly cut down to only the **segments** of the each bisector closest to the desired point 
			- Every segment of the $1$NN decision boundary is a perpendicular bisector of a line segment connecting two data points
			- Every segment of a $1$NN decision boundary is a straight line
			- However, not every perpendicular bisector is part of the $1$NN decision boundary
		- To complete the entire Voronoi Diagram, repeat this process for all training points and amalgamate the regions by classes into decision boundaries for the whole training set
	- Note the above assumed Euclidian distance being used
		- With Manhattan distance (only travelling along axes) draw an **axis-aligned rectangle with two points at opposite corners** and through its centre draw a $45^{\circ}$ diagonal **perpendicular** to the segment joining the points, stopping at the rectangle’s sides; thus, all boundaries are straight lines that are either axis-aligned or at $45^{\circ}$ angles
		- With Cosine distance **bisect the angle** between the rays from the origin to the points, rather than bisecting the line segment directly connecting them; go through points that are **adjacent in angular order** around the origin and draw the **angular bisector**, keeping it as a decision boundary only when the adjacent points have different classes
	- For kNNs with $k>1$, Voronoi diagrams become more a lot more complex to determine and are thus generally not used (and are not needed for inference anyways!) 

While kNNs are relatively simple and intuitive, and essentially do all their work at inference time, there are several challenges and downsides:
- Difference in **units of measurement** between features can make them disproportionately impactful; ex. if one dimension is measured in cm and another in mm, the same difference in mm would have a much larger impact on calculation of distance than if measured in cm
	- One method to mitigate this, assuming that we want each feature to be roughly equally impactful, is to **normalize** the data so that **all dimensions** have **zero mean** and **unit variance** (ie. are normally distributed)
		- Compute the mean $\mu_{j}$ and standard deviation $\sigma_{j}$ for each $j^{th}$ feature in the training set, then normalize as $\tilde{x}^{(i)}_{j}=\frac{x_{j}^{(i)}-\mu_{j}}{\sigma_{j}}$
		- Note, these statistics must be computed from **only the training set**, but they are applied when normalizing the relevant features in validation and test data as well
	- Note, this is an issue regardless of the measure of distance used!
- The **curse of dimensionality** states that in higher dimensional spaces, **most points are far apart** from each other as the data space expands **exponentially** with number of dimensions
	- Generally we want our training, validation, and test data to all be relatively close-by or in the same region (none of this is being rigorously defined for now but is intuitively clear) because training data will hold more information about closer test data than farther test data
		- Thus we need much **more training data** to have enough nearby points when working with high dimensional data that is representing many features
	- Furthermore, distances themselves become less informative in higher dimensions; most points become positioned approximately the **same distance** from any given query point, and thus the **nearest and farthest points can become relatively similar in distance**
		- This makes the entire notion of nearest neighbours less informative for the purposes of prediction
	- Simply increasing $k$ doesn't eliminate this underlying problem, as that comes with its own drawbacks as we have seen
- Since kNNs essentially have **no training phase** (**no parameters** or function), all computation is deferred to inference time; we need to store all the training data and compute distances to all training points at inference time, and the storage and distance computation costs can be prohibitively expensive for larger training sets
	- Thus, the computational complexity of kNNs inference is $\Theta(DN)$ where $D$ is the number of features and $N$ is the size of the training set, assuming the simplest case where we do not maintain a heap of distances of size $k$, etc.
# <u>2: Decision Trees</u>
## <u>Decision Trees</u>
Recall that a **decision boundary** partitions the data space into regions, where each region corresponds to a predicted class
- Unlike kNN decision boundaries which can be oriented in any direction, decision tree boundaries are **always axis-aligned** because each split tests a **threshold on a single feature** at a time
	- In two dimensions, this means every boundary is a horizontal or vertical line segment aligned with the axes; in higher dimensions, each boundary is a hyperplane perpendicular to one of the feature axes (ie. coefficients are all $0$ except for the variable on the axis which is perpendicular to the hyperplane)
	- To draw the boundaries of a decision tree, trace the splits from the root to the leaves and retain only those boundaries that separate regions of different predicted classes
A model class is a **universal function approximator** if for any continuous target function $f$ (i.e., any continuous ground-truth mapping from input to output) and for any desired level of approximation error $\epsilon$ (i.e., any degree of training accuracy), there exists some hypothesis $g$ such that $|g(x)-f(x)|<\epsilon$ for all $x$ in the domain (or a sufficiently large subset of the domain)

A decision tree is constructed through a **recursive splitting** procedure; start with all training points at the root node, then at each node choose a feature and a threshold to split the current points into two subsets based on whether they satisfy the condition, and set those subsets as the two subtrees
- It follows that decision trees are **binary trees**; each split partitions the current set into two
- Consider that after each split, we want each subset to be more **class-pure** than the original; then the key question is **which feature and threshold we should split on** at each step
	- Different split orders can produce very different trees, because an early split changes the subset of data seen by every later split
- Repeat the same procedure on each subset until a **stopping criterion** is reached, at which point each subset becomes a leaf node which is assigned a class label

To formalize the problem of **choosing the optimal split**, we define:
- **Hypothesis Space:** the set of all possible splits to consider at each node, and thus the set of all possible trees
- **Loss Function:** some measure of the quality of each split so we can compare them and pick the best one
One option is to treat the search for the optimal tree as a **global optimization problem**, where the hypothesis space is the set of all trees we can build from the training data, and the loss function is training error (of the finalized decision tree over the training set), but there are fatal flaws with this approach:
- Optimizing for training error leads to overfitting and poor generalization, and decision trees are in fact universal function approximators so a sufficiently large tree can classify the training set perfectly (a leaf per each training set point)
- Finding the **smallest** tree that perfectly classifies a training set is **NP-complete**, and thus computationally infeasible
A better option is a **greedy** strategy where the tree is build as a **local optimization problem**; aim to choose the locally optimal split at each node given only the data in that subset
- Since each split is not fully dependent on possible effects on future splits, this method will generally not produce a globally optimal tree
- Intuitively, we at least want conditions that split the data into two subsets with at least one data point in each subset; therefore, only consider splits that are within the range of values for the feature (a simple heuristic is to use the **midpoints** between consecutive values of a feature)
- Further limitations of using training error as the loss function:
	- One split can have a class-pure subset but still misclassify the same number of training points as another split which does not have the benefit of a class-pure subset
	- A split that doesn’t immediately decrease training error might still be valuable if it reduces uncertainty in a way that will help future splits
## <u>Information Theory</u>
**Information theory**, developed by Claude Shannon in the 1940s, provides a rigorous mathematical framework for quantifying **uncertainty** and **information**

**Entropy:** the entropy of a **discrete** random variable $X$ with probability mass function $p(x)$ is defined as 
$$
H(X)=-\mathbb{E}(\log_{2}p(X))=-\sum_{x \in X}\log_{2}p(x)\cdot p(x)
$$
This is the expected value of the transformation $\log_{2}p(X)$ on the random variable $X$
- For this definition, set $\log_{2}0=0$ by convention
- Entropy is measured in **bits**, because it is a lower bound on the number of bits needed to encode and store a sequence of outcomes of a random variable
- Entropy represents how much information we gain on average by observing a random draw from the distribution of $X$
	- If the outcome is completely predictable (one outcome has probability $1$), we gain no information by observing it so the entropy is $0$; ie. when a probability distribution is **concentrated** on a small number of outcomes, the entropy is low (ex. Bernoulli RV where one of the outcomes has probability $0$ and the other $1$ has $H(X)=0$)
	- If the outcome is completely unpredictable (uniform distribution), we gain a larger amount of information by observing it, so the entropy is larger; ie. when the distribution is spread **more evenly** across many outcomes, the entropy is high (ex. Bernoulli RV where both outcomes have probability $\frac{1}{2}$ has $H(X)=1$)

**Joint Entropy:** the entropy of **bivariate discrete** random variables $X,Y$ with joint probability mass function $p(x,y)$ is defined as 
$$
H(X,Y)=-\mathbb{E}(\log_{2}p(X,Y))=-\sum_{y\in Y}\sum_{x \in X}\log_{2}p(x,y)\cdot p(x,y)
$$
**Conditional Entropy:** the entropy of a **discrete** random variable $Y$ given the other bivariate random variable $X=x_{0}$ with joint probability mass function $p(x,y)$ is defined as
$$
H(Y|X=x_{0})=-\mathbb{E}(\log_{2}p(Y|X=x_{0}))=-\sum_{y\in Y}\log_{2}p(y|x_{0})\cdot p(y|x_{0})
$$
**Expected Conditional Entropy:** the entropy of $Y$ after observing $X$ in general (rather than a specific value); the probability weighted average of the conditional entropies of $Y$ for each value of $X$
$$
H(Y|X)=\mathbb{E}(H(Y|X=x))=\sum_{x\in X}H(Y|X=x)\cdot p(x)=\sum_{x\in X}\left(p(x)\cdot-\sum_{y \in Y}\log_{2}p(y|x)\cdot p(y|x)\right)=-\sum_{x\in X}\sum_{y \in Y}\log_{2}p(y|x)\cdot p(x,y)
$$
Some key algebraic properties of entropy:
- **Nonnegativity:** entropy is always nonnegative; that is $H(X)\geq 0$ for any RV $X$
- **The Chain Rule:** joint entropy can be decomposed as the entropy of one RV plus the conditional entropy of another given the first; $H(X,Y)=H(X|Y)+H(Y)=H(Y|X)+H(X)$
- **Independence:** if RVs $X,Y$ are independent, then they provide no information about each other; that is $H(Y|X)=H(Y)$ and $H(X|Y)=H(X)$, and $H(X,Y)=H(X)+H(Y)$
- **Information never increases entropy;** that is $H(Y|X)\leq H(Y)$
- **Perfect Information:** if $X$ completely determines $Y$ (ie. $Y$ is a single variable function of $X$), then $H(Y|X)=0$ as we learn nothing new by observing $Y$ after $X$

**Information Gain:** the information gain of a **discrete** random variable $Y$ with respect to $X$ is defined as
$$
IG(Y|X)=H(Y)-H(Y|X)
$$
Information gain measures how many bits of information about $Y$ we gain on average by observing $X$; it can also be interpreted as the reduction in uncertainty about $Y$ gained by knowing $X$
- Information gain is **always nonnegative**, following from the earlier fact that $H(Y|X)\leq H(Y)$
- If $X,Y$ are **independent** then $IG(Y|X)=0$, following from earlier fact that $H(Y|X)=H(Y)$ if the RVs are independent
- If $X$ completely determines $Y$ then $IG(Y|X)=H(Y)$, following from earlier fact that $H(Y|X)=0$
- Information gain is **symmetric**; that is $IG(Y|X)=IG(X|Y)$

Finally, we use information gain to make **locally optimal splitting decisions** when building decision trees
- Define $Y$ as an RV that maps to class labels, and $X$ as a binary (recall decision trees are binary) RV that represents which side of the proposed split a piece of data falls in
- We compute $H(Y)$ at each node, including the root, directly from the training set; with PMF values calculated as the occurrences of the class divided by the size of the training set
- Define $X_{1},\dots,X_{n}$ for $n$ possible choices of splits, each $X_{i}$ for $i\in[1,n]$ defined as $\{ 0,1 \}$ where $X_{i}=0$ indicates a data point lies in the left subtree and $X_{i}=1$ in the right, then compute:
	- $H(Y)$
	- $H(Y|X_{i}=0)$
	- $H(Y|X_{i}=1)$
	- $H(Y|X_{i})$ from the two above; where $p(0),p(1)$ are simply defined by the split
	- $IG(Y|X_{i})$ from the above
- Repeat the above for all $X_{i}$ and choose the arg maximum for $IG(Y|X_{i})$ as the optimal split
This is a shift from **deterministic** reasoning (using misclassification rate) to **probabilistic** reasoning (entropy reduction); it treats the **class label as a random variable** and directly measures how much **observing a feature** reduces uncertainty about it

Note even if features are continuous, the number of meaningful **splits we need to consider is finite** for a given dataset
- For a **binary** feature, there’s only one way to split
- For a feature with $k$ **categories**, there are $2^{k-1}-1$ ways to partition them into two groups
- For **continuous** features, use **midpoints between consecutive unique values**
- Thus, finding the optimal split is a finite task, and happens to be computationally feasible; however this may still be computationally heavy for larger datasets with many splits to consider
	- This is a significant tradeoff where we accept **training time complexity** to reduce **inference time complexity** (where simply traverse a binary tree); recall, kNNs take the opposite tradeoff
There are other tradeoffs for decision trees and information gain:
- **Gini impurity** generally results in similar trees as information gain, but is less computationally demanding (no logs)
- Information gain treats all misclassifications equally; in some contexts we want certain errors to be penalized more than others
- For regression tasks where the target variable is **continuous** rather than **discrete**, information gain is not usable as it is defined over discrete RVs 


Aside from splitting criteria, we must consider **stopping criteria**; when to stop splitting further and apply a classification to a leaf node
- Broadly, we want the shortest tree that does not underfit and miss important patterns
- While splitting criteria are model **parameters** determined by learning, stopping criteria are **hyperparameters** which can include:
	- Maximum depth
	- Minimum samples per node (recall, at each level there are less remaining samples)
	- Minimum samples per leaf (leaves with a single sample are sensitive to erroneous data and noise)
	- Minimum information gain (ie. stop splitting once uncertainty is no longer meaningfully reduced)
- Note, any of these hyperparameters may not yet be reached when a subtree becomes **class-pure**, at which point we of course stop splitting regardless
- Sometimes we **post-prune** trees; evaluate subtrees on the validation set and remove branches that do not improve validation performance


The entire algorithm can be summarized as follows:
1. **Start with all training data** at the root node
2. **For each node:**
	- Check if we should stop splitting
	- If stopping, create a leaf node with a class prediction (likely modal class of the subset)
    - Otherwise, find the best feature and split point (maximize information gain)
    - Split the data according to this feature and threshold
    - Recursively apply the algorithm to each child node
3. **Continue** until all branches end in leaf nodes; prediction of each leaf node is its **modal** class
# <u>3: Linear Regression</u>
## <u>Linear Regression</u>
For regression, we assume that there is an underlying function $f:\mathbb{R}^D\to \mathbb{R}$ that maps each $D$-dimensional feature vector to its corresponding continuous scalar output, and attempt to learn said function

For **linear regression**, the hypothesis space is restricted to functions of the form:
$$
y=f(\mathbf{x})=w_{1}x_{1}+w_{2}x_{2}+\dots+w_{D}x_{D}+b=\left(\sum_{j=1}^Dw_{j}x_{j}\right)+b
$$
Wherein:
- The vector $\mathbf{w}=[\begin{matrix} w_{1} & w_{2} & \dots & w_{D}  \end{matrix}]$ is the **weights vector** and controls the **magnitude** and **direction** of how each input feature affects the resulting prediction
- The scalar $b$ is the **bias** or **intercept** and is an offset term that shifts the prediction; this allows us to have models that do not necessarily pass through the **origin**
- Thus, $\mathbf{w}$ and $b$ are model **parameters**, and learning is the process of determining these values
So the hypothesis space is defined by the infinitely many choices of weights $\mathbf{w}$, each of which describes a **hyperplane** (line in $\mathbb{R}^2$, plane in $\mathbb{R}^3$, etc.)

Here $f$ is clearly a linear function, but this is easier to work with if we describe $f$ in **vectorized** (using vectors rather than summations of scalars) form:
$$
y=f(\mathbf{x})=\mathbf{w}^{\top}\mathbf{x}+b
$$
Vectorization has several benefits:
- Mathematically elegant and compact way to express operations on high-dimensional data
- Prerequisite for using parallelized computation on GPUs and ML libraries
- Allows us to clearly see and use properties of linear algebra, ie.: $\mathbf{w}^{\top}\mathbf{x}=\mathbf{x}^{\top}\mathbf{w}$
For full vectorization, we set a **dummy feature** $x_{0}=1$ and the corresponding **dummy weight** $w_{0}=b$, then:
$$
y=f(\mathbf{x})=\mathbf{w}^{\top}\mathbf{x}+b=\mathbf{w}^{\top}\mathbf{x}+1\cdot b=\mathbf{w}^{\top}\mathbf{x}+w_{0}\cdot x_{0}=\mathbf{w}'^{\top}\mathbf{x'}
$$
This form is the standard, and thus the primes are dropped from the final expression, then the **prediction vector** for a training set of size $N$ is $\mathbf{y}\in \mathbb{R}^N$ where $y^{(i)}=(\mathbf{x}^{(i)})^{\top}\mathbf{w}$
$$
\mathbf{y}=\left[\begin{matrix} y^{(1)} \\ y^{(2)} \\ \vdots \\ y^{N}\end{matrix}\right]=
\left[\begin{matrix} (\mathbf{x}^{(1)})^{\top}\mathbf{w} \\ (\mathbf{x}^{(2)})^{\top}\mathbf{w} \\ \vdots \\ (\mathbf{x}^{(N)})^{\top}\mathbf{w}\end{matrix}\right]=
\left[\begin{matrix} (\mathbf{x}^{(1)})^{\top} \\ (\mathbf{x}^{(2)})^{\top} \\ \vdots \\ (\mathbf{x}^{(N)})^{\top}\end{matrix}\right]\mathbf{w}
$$
We define the matrix of inputs as the **data matrix** $\mathbf{X}$, and thus overall:
- $\mathbf{y}\in \mathbb{R}^{N\times 1}$
- $\mathbf{t}\in \mathbb{R}^{N\times 1}$
- $\mathbf{X}\in \mathbb{R}^{N\times(D+1)}$, since each $(\mathbf{x}^{(i)})^{\top}\in \mathbb{R}^{1\times (D+1)}$
- $\mathbf{w}\in \mathbb{R}^{(D+1)\times 1}$
And finally; $\mathbf{y}=\mathbf{X}\mathbf{w}$


To optimize $\mathbf{w}$, we first need a **loss function** which measures the discrepancy between a model’s prediction and the ground-truth target value for any **one example**; for regression, we generally use **squared-error** loss: 
$$
\mathcal{L}^{(i)}(\mathbf{w})=\mathcal{L}^{(i)}(y^{(i)})=\frac{1}{2}(y^{(i)}-t^{(i)})^2=\frac{1}{2}(\mathbf{w}^{\top}\mathbf{x}^{(i)}-t^{(i)})^2
$$
Wherein:
- We want to minimize the **residual** $y^{(i)}-t^{(i)}$ (the division is done to simplify derivative calculations)
- We prefer squared-error over **absolute error** because the latter allows many shifted functions to achieve the same loss as long as the partition of points remains the same, while the former penalizes larger errors more heavily and pulls the the hyperplane to the 'middle' of the data  

The loss function measures the error for a single prediction and its corresponding target; we define a **cost function** which measures the **average loss across all training examples**, called **mean squared-error (MSE)**:
$$
\mathcal{E}(\mathbf{w}) = \frac{1}{N} \sum_{i = 1}^N \mathcal{L}^{(i)}(\mathbf{w}) = \frac{1}{2N} \sum_{i = 1}^N (y^{(i)}-t^{(i)})^2 = \frac{1}{2N} \sum_{i = 1}^N (\mathbf{w}^{\top}\mathbf{x}^{(i)}-t^{(i)})^2
$$
We can also vectorize the penultimate form above as:
$$
\mathcal{E}(\mathbf{w}) = \frac{1}{2N} \sum_{i = 1}^N (y^{(i)}-t^{(i)})^2 = \frac{1}{2N} (\mathbf{y}-\mathbf{t})^{\top}(\mathbf{y}-\mathbf{t}) = \frac{1}{2N} (\mathbf{X}\mathbf{w}-\mathbf{t})^{\top}(\mathbf{X}\mathbf{w}-\mathbf{t})
$$
Finally we identify the last term as the square of the $L_{2}$ norm of the vector $(\mathbf{X}\mathbf{w}-\mathbf{t})$ and thus write:
$$
\mathcal{E}(\mathbf{w}) = \frac{1}{2N} (\mathbf{X}\mathbf{w}-\mathbf{t})^{\top}(\mathbf{X}\mathbf{w}-\mathbf{t}) = \frac{1}{2N} ||\mathbf{X}\mathbf{w}-\mathbf{t}||_{2}^2
$$


The goal is to find parameters $\mathbf{w}^*=\text{argmin }\mathcal{E}(\mathbf{w})$, ie. weights that minimize the cost (average loss over the training set); we will first attempt a **direct solution** to find the minimum of the MSE
- Compute the gradient $\nabla\mathcal{E}(\mathbf{w})$
- Set $\nabla\mathcal{E}(\mathbf{w})=\mathbf{0}$
- Solve the system of equations (partial derivatives set to $0$) to determine weights where $\mathcal{E}$ has critical points, one of which may be a global minimum 
Recall, the gradient is the vector where the components are $\frac{\partial\mathcal{E}}{\partial w_{j}}$ for all $j \in[0,D]$, and since MSE averages out the loss function, we can simplify:
$$
\nabla\mathcal{E}(\mathbf{w})= \frac{1}{N} \sum_{i = 1}^N \nabla\mathcal{L}^{(i)}(\mathbf{w})
$$
Then, each $\nabla\mathcal{L}^{(i)}(\mathbf{w})$ is the vector where the components are $\frac{\partial\mathcal{L}^{(i)}}{\partial w_{j}}$ for all $j \in[0,D]$; we use the multivariable chain rule to determine each partial:
$$
\begin{align}
\frac{\partial\mathcal{L}^{(i)}}{\partial y^{(i)}}&=\frac{\partial}{\partial y^{(i)}} \frac{1}{2}(y^{(i)}-t^{(i)})^2=(y^{(i)}-t^{(i)})=(\mathbf{w}^{\top}\mathbf{x}^{(i)}-t^{(i)}) \tag{1} \\
\frac{\partial y^{(i)}}{\partial w_{j}}&=\frac{\partial}{\partial w_{j}}\mathbf{w}^{\top}\mathbf{x}^{(i)}=\frac{\partial}{\partial w_{j}}(w_{0}x^{(i)}_{0}+\dots+w_{j}x^{(i)}_{j}+\dots+w_{D}x^{(i)}_{D})=x^{(i)}_{j} \tag{2} \\
\frac{\partial\mathcal{L}^{(i)}}{\partial w_{j}}&=\frac{\partial\mathcal{L}^{(i)}}{\partial y^{(i)}}\cdot \frac{\partial y^{(i)}}{\partial w_{j}}=(\mathbf{w}^{\top}\mathbf{x}^{(i)}-t^{(i)})\cdot x^{(i)}_{j} \tag{by 1,2} \\
\end{align}
 $$
Then the entire gradient is the vector with all of these $(\mathbf{w}^{\top}\mathbf{x}^{(i)}-t^{(i)})\cdot x^{(i)}_{j}$ for all $j \in[0,D]$, which can be split out into a **scalar** by vector multiplication; so the components of the gradient of the loss function for the $i$th prediction are the error times each respective input feature:
$$
\nabla\mathcal{L}^{(i)}(\mathbf{w})=(\mathbf{w}^{\top}\mathbf{x}^{(i)}-t^{(i)})\mathbf{x}^{(i)}
$$
Then $\nabla\mathcal{L}^{(i)}(\mathbf{w})\in \mathbb{R}^{(D+1)\times 1}$ where each row entry is the respective $\frac{\partial\mathcal{L}^{(i)}}{\partial w_{j}}$, which we can substitute back into the cost gradient:
$$
\nabla\mathcal{E}(\mathbf{w})= \frac{1}{N} \sum_{i = 1}^N (\mathbf{w}^{\top}\mathbf{x}^{(i)}-t^{(i)})\mathbf{x}^{(i)}
$$
Then we vectorize this as:
$$
\nabla \mathcal{E}(\mathbf{w}) = \frac{1}{N} \mathbf{X}^\top (\mathbf{y} - \mathbf{t})=\frac{1}{N} \mathbf{X}^\top (\mathbf{X}\mathbf{w} - \mathbf{t})
$$

Then $\nabla \mathcal{E}(\mathbf{w})\in \mathbb{R}^{(D+1)\times 1}$ but with each row entry being the respective $\frac{1}{N} \sum_{i = 1}^N\frac{\partial\mathcal{L}^{(i)}}{\partial w_{j}}$; finally set it to $\mathbf{0}$ to solve for the optimal $\mathbf{w}$:
$$
\mathbf{0}=\frac{1}{N} \mathbf{X}^\top (\mathbf{X}\mathbf{w} - \mathbf{t}) \implies \mathbf{0}=\mathbf{X}^\top \mathbf{X}\mathbf{w} - \mathbf{X}^\top\mathbf{t}\implies \mathbf{X}^\top \mathbf{X}\mathbf{w} = \mathbf{X}^\top\mathbf{t}
$$
Which finally implies $\mathbf{w}=(\mathbf{X}^{\top}\mathbf{X})^{-1}\mathbf{X}^{\top}\mathbf{t}$
- A **unique** closed-form solution **exists** for the optimal weights of a linear regression because the cost over squared-loss objective is **convex** with a **single global minimum**
- However, there are drawbacks to the direct solution method:
	- The matrix inversion $(\mathbf{X}^{\top}\mathbf{X})^{-1}$ is $O(D^3)$ which becomes very costly as number of features grows, and doesn't help when the dataset itself is large either
	- While the unique solution exists for the linear regression with cost over squared-loss objective case, this does not generalize to most other contexts
## <u>Gradient Descent</u>
The **gradient descent** optimization algorithm for minimizing a function $f(\mathbf{w}):\mathbb{R}^D\to \mathbb{R}$ involves the following steps:
1. Initialize $\mathbf{w}\in \mathbb{R}^D$ to some initial values
2. Repeatedly apply the following update rule until a **stopping criterion** is met
$$
\mathbf{w}\leftarrow \mathbf{w}-\alpha \nabla f(\mathbf{w})
$$
Note that all components of $\mathbf{w}$ update simultaneously (not one coordinate at a time, otherwise earlier updates would affect where all other partials would be computed)
- The negation of the gradient is used, since the gradient points in the direction of steepest ascent
- The hyperparameter $\alpha>0$ is the **learning rate**
Recalling the expression for the gradient of the cost function $\nabla \mathcal{E}(\mathbf{w})$, we get:
$$
\mathbf{w}\leftarrow \mathbf{w}-\frac{\alpha}{N} \mathbf{X}^\top (\mathbf{X}\mathbf{w} - \mathbf{t})
$$
Gradient descent is a simple optimization method, but its use requires several considerations
- If $\alpha$ is **too small**, gradient descent can become computationally expensive and take too long; if $\alpha$ is **too large**, iterations of gradient descent can overshoot the targeted minimum and jump around it endlessly
	- In practice $\alpha$ is determined empirically using a **training curve** that simply compares values of $\mathcal{E}$ after each iteration using different $\alpha$
- Gradient descent uses only local information about the function, thus gradient descent is only able to find **local minima** (which may or may not be a global minimum)
	- This also depends on the initial vector; different initial points can lead to different local minima
	- However, this is not a concern for linear regression with squared-error; recall, the cost over squared-error function is **convex** with a **single global minimum**
The stopping criterion is used by gradient descent, but is not specified by the algorithm itself; we want to see $\mathcal{E}$ **converge** to the minimum but this is usually not computationally feasible
- In practice we simply define an **improvement threshold** for $\mathcal{E}$ and stop when iterations of gradient descent reduce $\mathcal{E}$ by less than that
- We may also set a **fixed cap on number of iterations**

**Feature scaling** through standardization (normalization) is recommended before running gradient descent to make the loss surface "rounder"
- Otherwise, features on smaller scales may have much larger partial derivatives and create **ravines** (steep on those dimensions, flat on the other dimensions) on the cost surface
	- This can cause the gradient descent algorithm to oscillate across the narrow dimension without moving much along the valley floor
- Normalization will not work for features that are **highly correlated** (ie. measure similar underlying characteristics of the data); they will still form a diagonal ravine relative to both features
- Note normalization is only applied to the data matrix $\mathbf{X}$, not $\mathbf{t}$
## <u>Feature Mapping</u>
Many datasets show clear nonlinear relationships; we can still use linear regression to model curves but with new features based on the original ones so that the non-linear relationships becomes linear in the transformed features

A **feature mapping** or basis expansion is a function $f:\mathbb{R}^D\to \mathbb{R}^{M+1}$ that maps each input $\mathbf{x}\in \mathbb{R}^D$ to a new feature vector $f(\mathbf{x})\in \mathbb{R}^{M+1}$
- To train a linear regression on these new features we replace the original training set with them, ie. $\{f(\mathbf{x})^{(i)},t^{(i)} \}_{i=1}^N$; note the targets remain unchanged
- Note, a feature mapping adds capacity only when the new features are **not linear combinations of the existing ones**; ie. linear combinations of linear transformations existing features are still linear!

The feature mapping can be any function; in practice the most frequently used is **polynomial feature mapping** where for a scalar input $x \in \mathbb{R}$ the map is:
$$
f(x)=\begin{matrix}[1&x&x^2&\dots&x^M]\end{matrix}^{\top}\in \mathbb{R}^{M+1}
$$
This mapping produces an $(M+1)$-dimensional feature vector, where $M$ is a hyperparameter called the **degree** of the polynomial
- The degree $M$ of the polynomial controls the number of input features, and thus the complexity of the resulting regression model
	- As we increase $M$, the model gains more parameters and becomes capable of fitting increasingly intricate patterns in the training data; however, a more complex model is not always a better model; $M$ too large can lead to overfitting, and too low to underfitting 
Such mappings lead to **polynomial regression** of degree $M$:
$$
y=w_{0}+w_{1}x+w_{2}x^2+\dots+w_{M}x^M=\sum_{j=0}^Mw_{j}x^{j}=\mathbf{w}^{\top}f(x)+w_{0}
$$

Another common choice for data with periodic structures is **sinusoidal (Fourier) mapping**
$$
f(x)=[\begin{matrix}1 & \sin(2\pi x) & \cos(2\pi x) & \sin(4\pi x) & \dots\end{matrix}]
$$

The resulting models after feature mapping are still **linear with regards to the weights**, regardless of whether the new features have nonlinear relationships to the original features
## <u>Regularization</u>
In general, large weights are undesirable because they mean that one feature contributes dominates the prediction; **large weights are often a sign of overfitting**
- But the **magnitudes of weights tend to increase with the number of features** in a model, while **MSE simultaneously falls**; we must balance between overfitting and loss

**Regularization** is a modification of the training procedure that prefers some models over others based on criteria other than the training error
- Commonly, regularization is used to improve generalization by preferring simpler models that reduce overfitting
- Performed by adding a penalty term to the MSE
$$
\mathcal{E}_{reg}(\mathbf{w})=\mathcal{E}(\mathbf{w})+\lambda \mathcal{R}(\mathbf{w})
$$
Wherein:
- $\mathcal{R}$ is the **regularization function** or **regularizer**; a penalty applied directly to the cost function to encode a preference for some models over others
- $\lambda$ is a **hyperparameter** that sets the relative importance of the MSE and the regularizer
A common choice for the regularizer is the $L_{2}$ regularizer:
$$
\mathcal{R}(\mathbf{w})=\frac{1}{2}\sum_{j=1}^Dw_{j}^2=\frac{1}{2}\mathbf{w}^{\top}\mathbf{w}=\frac{1}{2}||\mathbf{w}||_{2}^2
$$
Adding an $L_{2}$ penalty keeps the feature set (and thus $M$) fixed and instead discourages any weight from growing large by adding a cost for weight magnitude; this shrinks
the weights continuously toward zero rather than removing features outright
- The original cost term $\mathcal{E}(\mathbf{w})$ is minimized by **fitting the training data** as closely as possible, while the regularization term $\lambda\frac{1}{2}\mathbf{w}^{\top}\mathbf{w}$ is minimized by **making the weights small**; the hyperparameter $\lambda$ sets the relative importance of the two goals
# <u>4: Linear Classification</u>
## <u>Logistic Regression</u>
For classification, the targets are categorical; assuming binary classification we label each $t^{(i)}=0$ a **negative example** and $t^{(i)}=1$ a **positive example**

For a **binary classification** (two classes), one way we can go from a linear regression (producing a real number) to a binary predictor is to start with the linear regression:
$$
z=\left(\sum_{j=1}^Dw_{j}x_{j}\right)+b=\mathbf{w}^{\top}\mathbf{x}+b
$$
And from there create a piecewise function with a threshold $r$:
$$
y=
\begin{cases}
0 & \text{if } z < r \\
1 & \text{if } z \geq r  
\end{cases}
$$
We can further simplify this by noticing that the difference between the bias $b$ and the threshold $r$ is static, and thus for any inequality for ex. $\mathbf{w}^{\top}\mathbf{x}+b\geq r\implies \mathbf{w}^{\top}\mathbf{x}+(b-r)\geq 0$; then absorb this term into a dummy feature $x_{0}=1$ and dummy weight $w_{0}=b-r$:
$$
y=
\begin{cases}
0 & \text{if } \mathbf{w}^{\top}\mathbf{x}< 0 \\
1 & \text{if } \mathbf{w}^{\top}\mathbf{x}\geq 0  
\end{cases}
$$
Then the **decision boundary** is the **hyperplane** defined by the set $\{ \mathbf{x}:\mathbf{w}^{\top}\mathbf{x}=0 \}$
- In $\mathbb{R}^1$ (one feature) this is a point on the real line, in $\mathbb{R}^2$ (ie. two features) a line on the plane, in $\mathbb{R}^3$ a plane in space, etc.
- The choices of weights $\mathbf{w}$ (including the bias and threshold terms) changes the decision boundary; to work towards optimizing this decision boundary we need to consider the **weight space**

For each given training point $(\mathbf{x}^{(i)},t^{(i)})$, we can substitute the feature values and determine an inequality with regards to the weights, which determines the **halfspace** $\{ \mathbf{w}:\mathbf{w}^{\top}\mathbf{x}\geq -w_{0} \}$ assuming a positive example here; ie. the weight vectors in weight space which would correctly classify this training point 
- We take each of these inequalities as a constraint in a linear system; then the **intersection** of all these halfspaces is the **feasible region** in weight space where the weights **correctly classify all training** points
	- If this feasible region is nonempty, then it follows that a **hyperplane exists that perfectly separates the classes** and the training set is **linearly separable**
	- Finding points in a feasible set is efficiently solvable with linear programming methods, but in practice linearly separable data is rare; instead we focus on finding the good weights through optimizing a loss function


First we consider the **zero-one** loss function:
$$
\mathcal{L}_{0-1}^{(i)}(y^{(i)})=
\begin{cases}
0 & \text{if } y^{(i)}=t^{(i)} \\
1 & \text{otherwise }  
\end{cases}
=\mathbb{I}(y^{(i)}=t^{(i)})
$$
The corresponding cost function to this zero-one loss function then captures how many training set points are misclassified, and we simply seek to minimize that via gradient descent as with linear regression
- But this loss function is **constant** everywhere with respect to $z=\mathbf{w}^{\top}\mathbf{x}$ with a **step** at the decision boundary
	- Ex. for a negative example (ie. $t^{(i)}=0$) we have $\mathcal{L}_{0-1}^{(i)}=0$ when $z<0$ and $\mathcal{L}_{0-1}^{(i)}=1$ when $z\geq 0$, and vice versa for a positive example
	- Note this is with respect to $z$ which is the actual model prediction; $y$ is only a label that conveniently describes where $z$ is in relation to the decision boundary
- Then for a given training point $(\mathbf{x}^{(i)},t^{(i)})$ its partial with respect to a weight $w_{j}$ is:
$$
\frac{\partial\mathcal{L}_{0-1}^{(i)}}{\partial w_{j}}=\frac{d\mathcal{L}_{0-1}^{(i)}}{d z^{(i)}}\frac{\partial z^{(i)}}{\partial w_{j}}
$$
- But $\frac{d\mathcal{L}_{0-1}^{(i)}}{d z^{(i)}}=0$ everywhere except $z=0$ since the loss function is constant there, and $\frac{d\mathcal{L}_{0-1}^{(i)}}{d z^{(i)}}=\text{undefined}$ at $z=0$ due to the step so it is **not differentiable** there
	- This follows through to the final partials with respect to each weight by the Chain Rule, and thus we **do not have meaningful gradients** with which to run gradient descent with at any vector of weights!
	- Furthermore, this loss function **does not treat different magnitudes of error differently**; an incorrect prediction with $z$ close to the threshold is treated the same as one with $z$ being far from the threshold 

Next we consider the **squared-error** loss function, which was used for linear regression:
$$
\mathcal{L}_{SE}^{(i)}(z^{(i)})=\frac{1}{2}(z^{(i)}-t^{(i)})^2
$$
This function is **differentiable** and has **nonzero derivatives** with respect to $z$ **everywhere** as we saw with linear regression, unlike the zero-one loss
- Furthermore this is a function of $z$ rather than $y$, which immediately resolves the zero-one function's problem of not being affected by **different magnitudes of error** (in fact if we used $y$ this loss function would be identical to zero-one loss)
	- But this immediately introduces a new problem; **confidently correct predictions are reflected as large errors** just as if they were confidently incorrect
		- Thus, gradient descent would push the weights such that negative examples yield close to $z=0$ and positive examples close to $z=1$
			- But this is not meaningful for categorization; $z$ can be interpreted as the confidence of a prediction but it is not a classification in of itself ($y$ is), so we do not want it to match $t$
			- This suggests a potential solution; apply a **differentiable** function that restricts our prediction to the interval $[0,1]$, so that the error cannot exceed $1$


**Sigmoid Function:** also called the **logistic function**, where $z=\mathbf{w}^{\top}\mathbf{x}$ is called the **logit**
$$
y=\sigma(z)=\frac{1}{1+e^{-z}}
$$
The sigmoid function has several key properties:
- For all $z\in \mathbb{R}$, the function is bounded $0<\sigma(z)<1$
	- $\sigma(z)\to 1$ as $z\to \infty$
	- $\sigma(z)\to 0$ as $z\to -\infty$
	- $\sigma(0)=\frac{1}{2}$
- $\sigma(z)$ is strictly increasing
- $\sigma(z)$ is the CDF of the logistic distribution, with the PDF: $\frac{d}{dz}\sigma(z)=\sigma(z)(1-\sigma(z))$
	- This allows us to interpret $\sigma(z)$ as the **probability that an example belongs to the positive class**, given its score $z$
	- By convention for binary classification $\sigma(z)\geq \frac{1}{2}$ indicates a prediction of the **positive class**
		- As aforementioned this happens when $z=0$, thus the decision boundary is again the hyperplane $\{ \mathbf{x}:\mathbf{w}^{\top}\mathbf{x}=0 \}$
- The log-probability of the sigmoid is the inverse which takes us back to $z=\ln\left( \frac{\sigma(z)}{1-\sigma(z)} \right)$
	- Note then that the logistic regression model **linearly predicts log-odds** which is $z$, but the activated probability $y$ is **not a linear function** of $z$

We construct a new linear classification model with the sigmoid function and squared-error loss:
$$
\begin{align}
\text{Linear Model:\quad}&z=\mathbf{w}^{\top}\mathbf{x} \\
\text{Probability:\quad}&y=\sigma(z)=\frac{1}{1-e^{-z}} \\
\text{Loss:\quad}&\mathcal{L}_{SE}(y)=\frac{1}{2}(y-t)^2
\end{align}
$$
Then we can compute the gradient from the partials for each weight which are:
$$
\frac{\partial\mathcal{L}_{SE}^{(i)}}{\partial w_{j}}
=\frac{d\mathcal{L}_{SE}^{(i)}}{d y^{(i)}}\frac{dy^{(i)}}{dz^{(i)}}\frac{\partial z^{(i)}}{\partial w_{j}}
=(y^{(i)}-t^{(i)})\cdot y^{(i)}(1-y^{(i)})\cdot x_{j}^{(i)}
$$
Still, these partials show a clear problem with **gradient signal**; when the prediction is **very wrong** this function has critical points and the gradient approaches $0$, which stalls the gradient descent when it needs to move most!
- If $t=1$ and $z=-1000$, then $y=\sigma(z)\approx 0$ and the prediction is very wrong, but then $y(1-y)=0$ and thus the partial derivative of the loss for **all weights** approaches $0$, so gradient is $\mathbf{0}$
- If $t=0$ and $z=1000$, then $y=\sigma(z)\approx 1$ and the prediction is very wrong, but then $(y-t)=0$ and thus the partial derivative of the loss for **all weights** approaches $0$, so gradient is $\mathbf{0}$ 

Finally we look at the **cross-entropy** loss function, which works:
$$
\mathcal{L}_{CE}^{(i)}(y^{(i)})=
\begin{cases}
-\log(1-y^{(i)}) & \text{if } t^{(i)}=0 \\
-\log(y^{(i)}) & \text{if } t^{(i)}=1 \quad
\end{cases}
=-t^{(i)}\log(y^{(i)})-(1-t^{(i)})\log(1-y^{(i)})
$$
Then the behaviour of this loss function is:
- When $t=0$ as $y\to 0$ (increasingly confidently correct) the error $\mathcal{L}_{CE}^{(i)}\to-\log(1-0)=0$
- When $t=0$ as $y\to 1$ (increasingly confidently wrong) the error $\mathcal{L}_{CE}^{(i)}\to-\log(1-1)=\infty$
- When $t=1$ as $y\to 0$ (increasingly confidently wrong) the error $\mathcal{L}_{CE}^{(i)}\to-\log(0)=\infty$
- When $t=1$ as $y\to 1$ (increasingly confidently correct) the error $\mathcal{L}_{CE}^{(i)}\to-\log(1)=0$
Moreover, the partial derivatives are as follows:
$$
\frac{\partial\mathcal{L}_{CE}^{(i)}}{\partial w_{j}}
=\frac{d\mathcal{L}_{CE}^{(i)}}{d y^{(i)}}\frac{dy^{(i)}}{dz^{(i)}}\frac{\partial z^{(i)}}{\partial w_{j}}
=\left(-\frac{t^{(i)}}{y^{(i)}}-\left(-\frac{1-t^{(i)}}{1-y^{(i)}}\right)\right)\cdot y^{(i)}(1-y^{(i)})\cdot x_{j}^{(i)}
=(y^{(i)}-t^{(i)})x_{j}^{(i)}
$$
Then mapping each partial to a component of the gradient for each weight gives:
$$
\nabla_{\mathbf{w}}\mathcal{L}_{CE}^{(i)}=(y^{(i)}-t^{(i)})\mathbf{x}^{(i)}
$$
The behaviours of this cross-entropy loss function perfectly capture the information that we want the loss measure to convey, and its gradient only approaches $0$ when predictions are confidently correct (rather than confidently wrong as with squared-error)!
- Furthermore, the gradient has a simple final form and that is easy to compute; what remains is the error, so the **size of the gradient now reflects how wrong the prediction is**
	- When the prediction is far from the target the gradient stays large in magnitude, encouraging the model to make larger weight updates; and to make smaller updates when the prediction gets close to target
- Minimizing this loss corresponds to **maximum likelihood estimation** which will be covered in Chapter 7

Then the cross-entropy cost function for an $N$ sample training set is: 
$$
\mathcal{E}(\mathbf{w})
=\frac{1}{N} \sum_{i = 1}^N \mathcal{L}^{(i)}(y^{(i)})
=\frac{1}{N} \sum_{i = 1}^N-t^{(i)}\log(y^{(i)})-(1-t^{(i)})\log(1-y^{(i)})
$$
From which the gradient is:
$$
\nabla\mathcal{E}(\mathbf{w})
=\frac{1}{N} \sum_{i = 1}^N \nabla\mathcal{L}^{(i)}(y^{(i)})
=\frac{1}{N} \sum_{i = 1}^N (y^{(i)}-t^{(i)})\mathbf{x}^{(i)}
$$
And finally the gradient descent:
$$
\mathbf{w}\leftarrow \mathbf{w}-\frac{\alpha}{N} \sum_{i = 1}^N (y^{(i)}-t^{(i)})\mathbf{x}^{(i)}
$$
Notice that this logistic regression cross-entropy cost function gradient and descent is the **same as a linear regression squared-error cost function** gradient and descent
- Despite the fact that the linear prediction $y^{(i)}=\mathbf{w}^{\top}\mathbf{x}^{(i)}$ is now used as an intermediate value $y^{(i)}=\sigma(\mathbf{w}^{\top}\mathbf{x}^{(i)})$

Like with linear regression, **feature scaling** is recommended before running linear regression, using the means and standard deviations of features in the training set:
$$
\begin{align}
\tilde{x}_j = \frac{x_j - \mu_j}{\sigma_j}
\end{align}
$$

Logistic regression are **parametric**; their hypothesis space can be characterized by a fixed-size finite set of parameters (in this case $\mathbf{w}$) and the training data thereafter is not required at all for inference
- kNNs in contrast are **non-parametric**; the complexity of the hypothesis can grow infinitely with the amount of training data, in the case of kNNs linearly with the size of the training set
**Inductive Bias:** of a machine learning algorithm is the set of assumptions or preferences that guide how it generalizes from training data to new, unseen examples; these assumptions determine what patterns the algorithm can learn and how it interpolates between training points
- The inductive bias of logistic regression is that the classes can be separated by a linear decision boundary, a hyperplane; this underfits when the boundary between classes is nonlinear
	- Logistic regression is also easily **interpretable**; the weights tell us which features matter most and in which direction 
- The inductive bias of kNN is that similar inputs should have similar outputs, so it can represent arbitrarily complex boundaries given enough data
	- A strong assumption which helps kNNs when it matches the data and hurts when it does not
## <u>Stochastic Gradient Descent</u>
**Full-batch gradient descent** is what we have been using so far:
$$
\mathbf{w} \leftarrow \mathbf{w} - \alpha \frac{1}{N} \sum_{i=1}^{N} \nabla_{\mathbf{w}} \mathcal{L}^{(i)}(y^{(i)})
$$

**Stochastic gradient descent** chooses **one** uniformly random training example $i$ per iteration, and uses its **loss function gradient** for updating:
$$
\mathbf{w} \leftarrow \mathbf{w} - \alpha \nabla_{\mathbf{w}} \mathcal{L}^{(i)}(y^{(i)})
$$
Benefits of stochastic gradient descent:
- Computational cost of each iteration is very low, and is **constant** with regards to the size of the training set $N$, whereas full-batch scales linearly with $N$
- Mathematically, it provides an **unbiased estimate of the full-batch gradient at each iteration**, as long as we perform uniform random sampling
- For data which is inherently large in memory (ex. video and images), stochastic gradient descent may be necessary to make gradient descent computationally feasible
Drawbacks of stochastic gradient descent:
- While it is an unbiased estimate of the full-batch gradient at each iteration, it is obviously **noisy**
- Cannot take advantage of vectorization and parallelization in hardware

**Mini-batch gradient descent** is technically also stochastic, in that it chooses a subset **batch** of training examples per iteration, and uses its **cost function gradient** for updating:
$$
\mathbf{w} \leftarrow \mathbf{w} - \alpha \frac{1}{k} \sum_{i \in \mathcal{B}} \nabla_{\mathbf{w}} \mathcal{L}^{(i)}(y^{(i)})
$$
Where:
- The **batch size** is $k$ and each batch is $\mathcal{B}=\{ i_{1},i_{2},\dots,i_{k} \}$
- The batches **partition** the training set and are chosen by randomly permuting the training set
- At each iteration we use one batch **without replacement**; an **epoch** of mini-batch gradient descent is complete once all batches have been used in one iteration for total of $\frac{N}{k}$ iterations
	- Then, for full-batch gradient descent each iteration is essentially an entire epoch
The benefits of mini-batch gradient descent:
- Computational cost of each iteration is lower than full-batch
- Since the mini-batches are sampled at random, the gradient estimate at each iteration is correct on average; it is an **unbiased estimate of the true full-batch gradient**
- Can take advantage of vectorization and parallelization in hardware given a large enough batch size $k$
Drawbacks of stochastic gradient descent:
- Mini-batch gradient descent follows the gradient of the mini-batch cost, not the gradient of the full training cost; thus, the gradient estimate at any single iteration can point in a different direction from the full-batch gradient 
- While it is an unbiased estimate of the full-batch gradient at each iteration, it is obviously **noisy**; however, this noise causes the gradient descent to be more erratic and less smooth which sometimes helps it **escape suboptimal local minima**
Further considerations for mini-batch gradient descent:
- When using smaller batches (which produce noisier gradient estimates), it is often beneficial to use a **smaller learning rate** $\alpha$ to compensate for the increased noise and prevent divergence
	- Conversely, larger batches with more accurate gradient estimates can often tolerate larger learning rates
- The randomness introduced by sampling mini-batches can sometimes help escape **plateaus** (where $\mathcal{E}$ is not at a minimum but is flat and thus has $\mathbf{0}$ gradient), as the noisy gradient estimates may occasionally point in directions that lead out of the flat region
	- However, it is best to **construct cost functions to avoid plateaus** if possible
- When features are **not normalized**, or are **correlated**, the cost function can present **ravines** which either makes the function wildly oscillate about the ravine (with a higher $\alpha$) or make very slow progress (with a relatively smaller $\alpha$)
## <u>Softmax Regression for Multi-Class Classification</u>
For binary classification with $K=2$ the target was labelled $t^{(i)}\in \{ 0,1 \}$; now we extend logistic regression to **multi-class classification** where each input example belongs to exactly one of possible $K\geq 3$ classes
- Initially we consider using $t^{(i)}\in \{ 0,1,\dots,K-1 \}$ but this would imply that the classes have meaningful **ordering** and **distances** among each other as measured by the labels, which is not the case for classification
	- Instead we use **one-hot vectors**; each target is $\mathbf{t}^{(i)}\in \mathbb{R}^K$ where the $k^{th}$ component of the vector is $1$ for class $K=k$ and all other components are $0$
	- Then the training set becomes $\{ (\mathbf{x}^{(1)},\mathbf{t}^{(1)}),(\mathbf{x}^{(2)},\mathbf{t}^{(2)}),\dots,(\mathbf{x}^{(K)},\mathbf{t}^{(K)}) \}$

The next major difference from binary classification is that we now have a **separate linear model for each class**, where for each class $k$ the logit is:
$$
z_{k}=\mathbf{w}_{k}^{\top}\mathbf{x}
$$
Then, for each example there is vector of logits $\mathbf{z}\in \mathbb{R}^K$ such that:
$$
\mathbf{z}=\begin{bmatrix} z_1 \\ z_2 \\ \vdots \\ z_K \end{bmatrix}
=\begin{bmatrix} \mathbf{w}_{1}^{\top}\mathbf{x} \\ \mathbf{w}_{2}^{\top}\mathbf{x} \\ \vdots \\ \mathbf{w}_{K}^{\top}\mathbf{x} \end{bmatrix}
$$
From this we can split out a **weights matrix** where $\mathbf{W}\in \mathbb{R}^{K\times (D+1)}$:
$$
\mathbf{z}=\mathbf{W}\mathbf{x}
=
\begin{bmatrix}
b_{1} & w_{1,1} & w_{1,2} & \cdots & w_{1,D} \\
b_{2} & w_{2,1} & w_{2,2} & \cdots & w_{2,D} \\
\vdots & \vdots & \vdots & \ddots & \vdots \\
b_{K} & w_{K,1} & w_{K,2} & \cdots & w_{K,D}
\end{bmatrix}
\begin{bmatrix}
1 \\
x_{1} \\
\vdots \\
x_{D} 
\end{bmatrix}
$$
At this stage:
- The $k$-th row of $\mathbf{W}$ is the weights of the linear model for predicting whether the example is of class $k$, and has $D+1$ parameters to match the $D$ features and dummy feature for the bias
- The scores in $\mathbf{z}$ are **logits** or **pre-activations**; they are unnormalized and cannot yet be interpreted as probabilities, which we will resolve with the softmax function as we did with the sigmoid for binary classification


**Softmax Function:** just as the sigmoid maps a single logit to a probability, the softmax function maps a vector of logits to a **probability distribution over** $K$ **classes**; given a vector of logits $\mathbf{z}\in \mathbb{R}^K$ where $z_{k}$ is the logit for class $k$, the softmax function produces a vector of $\mathbf{y}\in \mathbb{R}^K$ predictions , where the predicted probability for each class $k$ is:
$$
y_{k}=\frac{e^{z_{k}}}{\sum_{k'=1}^Ke^{z_{k'}}}
$$
And the resulting softmax function is:
$$
\mathbf{y}=\text{softmax}(\mathbf{z})=\begin{bmatrix} y_1 \\ y_2 \\ \vdots \\ y_K \end{bmatrix}
=\begin{bmatrix} \frac{e^{z_{1}}}{\sum_{k'=1}^Ke^{z_{k'}}} \\ \frac{e^{z_{2}}}{\sum_{k'=1}^Ke^{z_{k'}}} \\ \vdots \\ \frac{e^{z_{K}}}{\sum_{k'=1}^Ke^{z_{k'}}} \end{bmatrix}
$$
The softmax function has several key properties:
- Since $\exp(x)>0$, for all $k\in \{ 1,2,\dots,K \}$ we have $0 \leq y_k \leq 1$ and $\sum_{k=1}^K y_k = 1$, so each $y_{k}$ can now be interpreted as a probability and $\mathbf{y}$ as a probability distribution over $K$ classes
- Since $\exp(x)$ is strictly increasing, softmax **preserves the ordering of the logits** in $\mathbf{z}$; in fact **during inference we can skip the softmax calculation** and simply choose the greatest logit, but softmax gives us what we can interpret as the **confidence** of the prediction
- It can be viewed as a **smooth, differentiable** approximation to the **argmax** operation on the logits; this is **why need the softmax calculation during training**, to facilitate gradient descent
- Lastly consider that softmax is a generalization of the sigmoid; the **sigmoid is a special case of softmax** for $K=2$

There are now **multiple decision boundaries**; recall that the decision boundary is the set of points where the model’s prediction would change if the input changes a little bit
- Since the model predicts the class with the highest score, the prediction changes where the highest score switches from one class to another; this happens where **two classes tie for the highest score**
	- That is, a point $\mathbf{x}$ lies on the decision boundary between classes $a$ and $b$ if their logits are the same $\mathbf{w}_{a}^{\top}\mathbf{x}=\mathbf{w}_{b}^{\top}\mathbf{x}$, and **no other class has a larger score** 
		- Both conditions are necessary; if another class $c$ has a larger score, the model predicts the class $c$, and changing a little bit does not change the prediction
		- Consider that $\mathbf{w}_{a}^{\top}\mathbf{x}=\mathbf{w}_{b}^{\top}\mathbf{x}$ is equivalent to $(\mathbf{w}_{a}^{\top}-\mathbf{w}_{b}^{\top})\mathbf{x}=0$ which defines a **hyperplane** which is the decision boundary between the two classes
		- To determine the decision boundaries, set up the above hyperplane equations for all combinations of classes to determine the hyperplanes
			- Then discern the specific parts of the boundaries by applying the second condition where the remaining classes' logits must be less (or draw the full hyperplanes and simply check points by substitution, verifying which halfspaces lead to which class having the highest logit)


Finally, for training to choose the parameters $\mathbf{W}$ such that the predictions produced during inference match the labelled data as closely as possible, we optimize the cross-entropy cost function, where the loss generalizes from the sigmoid loss:
$$
\mathcal{L}_{CE}^{(i)}(\mathbf{y}^{(i)})= -t_1^{(i)} \log(y_1^{(i)}) -t_2^{(i)} \log(y_2^{(i)}) - \dots - t_K^{(i)} \log(y_K^{(i)}) 
=\sum_{k=1}^K t_k^{(i)} \log(y_k^{(i)})
=-\mathbf{t}^{(i)\top}\log (\mathbf{y}^{(i)})
$$
Notice that only **one term in this loss function is nonzero** since $\mathbf{t}^{(i)}$ is a one-hot vector at component $k$; the expression simplifies to the negative log-probability (not log-odds like in sigmoid binary classification!) assigned to the class of $i$, so the loss **penalizes the model whenever it assigns low probability to the correct class** 

Lastly the loss function gradient simplifies to:
$$
\nabla \mathcal{L}_{\text{CE}}^{(i)}= (y_k^{(i)} - t_k^{(i)}) \mathbf{x}^{(i)}
$$
And the gradient descent update to:
$$
\mathbf{w} \leftarrow \mathbf{w}  - \frac{\alpha}{N} \sum_{i=1}^{N} (y^{(i)}_k - t^{(i)}_k)\mathbf{x}^{(i)}
$$
## <u>Limitations of Linear Models</u>
Consider that decision boundaries between classes may be nonlinear, disconnected, etc. all of which linear models cannot capture

For example, the **XOR** dataset $\oplus(x_{1},x_{2})$ is **not linearly separable**, ie. there is no hyperplane that perfectly classifies the outputs of the function
- We can prove this **algebraically**:
	- Assume a logistic regression classifier with threshold $z=0$ and a positive prediction for $z\geq 0$, then the constraints for a perfect classifier are:
		- For $x_{1}=0,x_{2}=0$, we have $t=0$ and thus $b+w_{1}x_{1}+w_{2}x_{2}=b< 0$
		- For $x_{1}=1,x_{2}=0$, we have $t=1$ and thus $b+w_{1}x_{1}+w_{2}x_{2}=b+w_{1}\geq 0$
		- For $x_{1}=0,x_{2}=1$, we have $t=1$ and thus $b+w_{1}x_{1}+w_{2}x_{2}=b+w_{2}\geq 0$
		- For $x_{1}=1,x_{2}=1$, we have $t=0$ and thus $b+w_{1}x_{1}+w_{2}x_{2}=b+w_{1}+w_{2}< 0$
	- Summing the constraints for the negative examples yields $2b+w_{1}+w_{2}<0$ while summing the positive examples yields $2b+w_{1}+w_{2}\geq 0$, so there are no solutions
- We can also prove this **geometrically**:
	- The two line segments that connect $(0,0),(1,1)$, and $(1,0),(0,1)$ both intersect at $(0.5,0.5)$ and we can prove via convexity that this intersection lies in both halfspaces defined by the decision boundary, which is a contradiction

 Feature mapping can create more expressive models and determine valid nonlinear decision boundaries (recall, linear models are **linear in the weights**) where there previously were not any
 - However, the choice of features requires domain knowledge and manual experimentation; the right interactions between features are not obvious
 - Moreover, the number of possible features grows combinatorially; for $D$ features, all degree $2$ products (ex. $x_{1}^2x_{2}$) give $O(D^2)$ new features, which becomes infeasible for high-dimensional data
 - The motivation for neural networks; rather than hand-crafting feature maps, we will build models that learn nonlinear representations directly from data
# <u>5: Neural Networks</u>
## <u>The Neuron</u>
An artificial neuron takes an input vector $\mathbf{x}$ and computes a weighted sum of the inputs plus a bias $\mathbf{w}^\top \mathbf{x} + b$; this quantity is called the **pre-activation** which the neuron then passes through an **activation function** $f$, which is typically **nonlinear**, to produce the output $y=f(\mathbf{w}^\top \mathbf{x} + b)$
- Logistic and softmax regression can each be interpreted as a single artificial neuron, or equivalently a small one-layer neural network that applies a linear transformation to its input and then passes the result through the sigmoid or softmax activation functions
	- If interpreted as such, the logistic neuron produces one output whereas the softmax neuron produces $K$ outputs 
- The natural next step is to **stack layers** of neurons; by composing several linear transformations with nonlinear activation functions, a network can represent the complex decision boundaries that a single layer cannot
## <u>The Multi-Layer Perceptron</u>
**Unit:** any node in a neural network
- **Input Layer:** represents the input features to the model; each input unit acts like a sensor that reports one measurement but does not perform any computation and simply holds the data, so it is a unit but not a neuron
**Neuron:** a unit that computes its output from its inputs
- **Computational Layer:** a layer of neurons; ie. a layer in which units transform some inputs to some outputs
- **Output Layer:** a computational layer that produces values that have a clear interpretation; for a classification task the outputs typically represent a probability distribution over classes, for a regression task a continuous value
- **Hidden Layer:** any computational layer between the input layer and output layer; the outputs of the hidden units are internal model representations rather than observed data or final predictions; essential for modelling nonlinear relationships
- **Fully Connected Layer:** a layer in which **every** unit receives input from **every** unit in the preceding layer, and only from those units
**Feedforward Neural Network:** a neural network whose computation flows only from earlier layers (but not necessarily the preceding layer) to later layers with no feedback loops, ie. a **directed acyclic graph** (DAG)

**Multi-Layer Perceptron:** an MLP is a **feedforward** neural network with **one or more hidden layers** between the input and output layers, in which **every layer is fully connected**
- The notation $m$-layer MLP implies $m-1$ hidden layers and an output layer; then input layer is indexed $0$ and the output layer is indexed $m$
- $D^{(i)}$ is the number of units in the $i$th layer, then:
	- Input layer is $\mathbf{a}^{(0)}\in \mathbb{R}^{D^{(0)}}$
	- Weights matrix is $\mathbf{W}^{(i)}\in \mathbb{R}^{D^{(i)}\times D^{(i-1)}}$ where $W_{j,k}^{(i)}$ is the weight applied to the output of unit $k$ in layer $i-1$ to produce the output of unit $j$ in layer $i$
	- Bias vector $\mathbf{b}^{(i)}\in \mathbb{R}^{D^{(i)}}$ where $b_{j}^{(i)}$ is the bias of the $j$th unit 
	- Pre-activations $\mathbf{z}^{(i)}\in \mathbb{R}^{D^{(i)}}$ where $z_{j}^{(i)}$ is the pre-activation of the $j$th unit and $\mathbf{z}^{(i)}=\mathbf{W}^{(i)}\mathbf{a}^{(i-1)}+\mathbf{b}^{(i)}$
	- Activations are $\mathbf{a}^{(i)}\in \mathbb{R}^{D^{(i)}}$ where $a_{j}^{(i)}$ is the activation of the $j$th unit; these activations are computed as $f^{(i)}(\mathbf{W}^{(i)}\mathbf{a}^{(i-1)}+\mathbf{b^{(i)}})=f^{(i)}(\mathbf{z}^{(i)})=\mathbf{a}^{(i)}$ 
	- Activation function is $f^{(i)}$; note this is specific to the layer
	- Final prediction is $\mathbf{a}^{(m)}\in \mathbb{R}^{D^{(m)}}$ where for $\mathbf{t}\in \mathbb{R}^n$ we have $D^{(m)}=n$


Any given activation function in an MLP generally takes the form $f:\mathbb{R}\to \mathbb{R}$ and is **nonlinear**
- Nonlinear activation functions are the source of nonlinearity in MLPs; with linear activation functions an MLP would be linear and could be reduced to just one layer with function composition, thus choice of activation functions is key
- Generally, the activation function at a layer $i$ is applied element-wise to the pre-activations to determine the activations, ie. $\mathbf{a}^{(i)}=f^{(i)}(\mathbf{z}^{(i)})$; the **softmax activation function is an exception** which generates a discrete probability distribution over the units
- There are four types of activation functions generally used in simpler MLPs

The **sigmoid** function, as we already encountered in logistic regression, which has two appealing properties as an activation function
- The sigmoid is a smooth and everywhere-differentiable approximation of the threshold / step function, which makes gradient descent based training possible
- It mirrors the biological intuition of a neuron firing; instead of treating a neuron as either firing or not firing, we can interpret the sigmoid’s output as the neuron’s rate of firing, or the probability that it fires
==However the sigmoid also had its drawbacks: come back to this after backprop==
- **Saturation:** when $|z|$ is large (ie. very confident), the sigmoid is nearly flat as it asymptotically approaches $0$ or $1$; thus the derivative approaches $0$ and gradient descent barely updates a saturated unit's incoming weights, even if the prediction is wrong
- **Vanishing Gradient:** even for deep MLPs with no saturated units,

## <u>Maximum Likelihood and Maximum-a-Posteriori</u>
Let $\mathcal{D}=x^{(1)},x^{(2)},\dots,x^{(n)}$ be **iid** observed data points 

**Likelihood Function:** tells us how likely the observed sample $\mathcal{D}\in \mathbb{R}^n$ is, as a function of the value of the parameter $\theta$
$$
L(\theta)=P(\mathcal{D};\theta)=\prod_{i=1}^nP(X=x^{(i)};\theta)
$$
Intuitively this is simply the **joint probability** $P(X^{(1)}=x^{(1)},X^{(2)}=x^{(2)},\dots,X^{(n)}=x^{(n)};\theta)$; the probability of observing our data $\mathcal{D}$ for a value of $\theta$
- By the iid assumption the data is independent and comes from one distribution, which is why the joint probability is simply $\prod_{i=1}^nP(X=x^{(i)};\theta)$
- Maximizing the likelihood gives the parameter value for which the observed sample is most likely to have been generated

**Maximum Likelihood Estimate:** the MLE is the value of $\theta$ for which the likelihood function is maximized; and thus is the value of $\theta$ where the probability of observing $\mathcal{D}$ is maximized
$$
\hat{\theta}_{\text{MLE}}=\arg\max_{\theta \in\mathcal{R}}L(\theta)=\arg\max_{\theta \in\mathcal{R}}P(\mathcal{D};\theta)
$$
Where $\mathcal{R}$ is the range of $\theta$, which depends on the underlying distribution of $X$
- For simple and agreeable distributions, this value is determined by **solving for** $\theta$ in the derivative $\frac{d}{d\theta}L(\theta)=0$ because the likelihood is concave and thus has a maximum at this critical point
	- To make the derivative calculation simpler still we often swap in the **log-likelihood function** which is $l(\theta)=\ln(L(\theta))=\sum_{i=1}^n\ln P(X=x^{(i)};\theta)$, which works because
		1. The $\ln$ function is strictly increasing; the log-likelihood has its maximum at exactly the same $\theta$ as $L(\theta)$ does so nothing is lost
		2. The $\ln$ function turns products into sums, which are efficient to compute and far easier to differentiate
		3. The $\ln$ function is numerically stable; a product of many numbers each of which is $\leq 1$ (which $L(\theta)$ often is since it is a joint probability) often goes to $0$, but a sum of their logs does not

The MLE has two major flaws:
- With limited data, it can overfit to the given sample; ex. take a few iid Bernoulli samples which are all negative, then the MLE is necessarily $\hat{\theta}_{\text{MLE}}=0$ where $\theta$ is the probability of success
- The MLE uses only the observed samples together with an assumption about the underlying iid distribution type; it does not take into account any a priori assumptions about $\theta$


**Posterior Probability:** is a **conditional probability distribution** that represents the updated belief about a parameter after observing data $\mathcal{D}$
$$
P(\theta\mid\mathcal{D})
=\frac{P(\mathcal{D} \mid \theta) P(\theta)}{P(\mathcal{D})}
\propto P(\mathcal{D} \mid \theta)\cdot P(\theta)
$$
Notice then that posterior probability is derived by updating the prior probability $P(\theta)$ with information summarized by the likelihood function via Bayes' theorem

Assume the underlying distribution of $\mathcal{D}$ is **Bernoulli** with its one parameter, probability of success, being $\theta$, then:
- The term $P(\theta)$ is our **a priori estimate of the success probability parameter's distribution**; since this is $\in[0,1]$ it is best modelled using the **Beta distribution** where $P(\theta;\alpha,\beta)\propto \theta^{\alpha-1}(1-\theta)^{\beta-1}$
	- The Beta distribution is symmetric and centered at $0.5$ when $\alpha=\beta$, and is simply the uniform distribution when $\alpha=\beta=1$
	- When $\alpha\neq\beta$, the distribution is skewed toward the larger parameter
		- Increasing $\alpha$ shifts the distribution toward $1$, and increasing $\beta$ shifts it toward $0$
	- Finally as $\alpha+\beta$ becomes larger the distribution has a higher peak, meaning that it concentrates more of its density around its expectation; more confidence
	- Ultimately $\alpha$ and $\beta$ can be interpreted as **pseudo-counts**; we pretend to have observed $\alpha-1$ successes and $\beta-1$ failures before calculating the MAP
- Then $P(\mathcal{D} \mid \theta) \ P(\theta) \propto\theta^{N_{\text{win}}} (1 - \theta)^{N_{\text{loss}}}\theta^{(\alpha - 1)} (1 - \theta)^{(\beta - 1)} = \theta^{(N_{\text{win}} + \alpha - 1)} (1 - \theta)^{(N_{\text{loss}} + \beta - 1)}$, which suggests that the posterior $P(\theta\mid\mathcal{D})$ itself a Beta distribution with params $\alpha+N_{\text{win}}$ and $\beta+N_{\text{loss}}$
	- Because the **prior and posterior belong to the same family**, the Beta is a **conjugate prior** for the **Bernoulli likelihood**
		- Conjugate priors simplify the math because the posterior has a closed form in the same family as the prior, so updating our beliefs just means updating the prior’s parameters

**Maximum a-Posteriori Estimate:** the MAP estimate of $\theta$ is the **mode of the posterior distribution**; the **single value** of $\theta$ that has the highest posterior probability density, given the observed sample $\mathcal{D}$
$$
\hat{\theta}_{\text{MAP}}=\arg\max_{\theta \in\mathcal{R}}P(\theta\mid\mathcal{D})
$$
Recall by using Bayes' Theorem we can rewrite this and drop the $P(\mathcal{D})$ denominator since it does not affect the $\arg\max$ function:
$$
\hat{\theta}_{\text{MAP}}=\arg\max_{\theta\in\mathcal{R}}P(\theta\mid\mathcal{D})
=\arg\max_{\theta \in [0, 1]} \frac{P(\mathcal{D} \mid \theta) P(\theta)}{P(\mathcal{D})}
\approx \arg\max_{\theta \in [0, 1]}P(\mathcal{D} \mid \theta)\cdot P(\theta)
$$
The process to compute the MAP is similar to computing the MLE:
- First we take the natural logarithm of the posterior probability; $\ln P(\theta \mid \mathcal{D}) = (N_{\text{win}} + \alpha - 1) \log (\theta) +  (N_{\text{loss}} + \beta - 1) \log (1 - \theta) + \text{const}$
- Then take the derivative, set to $0$, and solve for $\theta$, which in the Bernoulli and Beta case is $\hat{\theta}_{\text{MAP}} =\frac{N_{\text{win}} + \alpha - 1}{N_{\text{win}} + N_{\text{loss}} + \alpha + \beta - 2}$
	- Intuitively, we can think of this as adding $\alpha-1$ successes and $\beta-1$ failures through our priors to the $\theta$ suggested only by the observed data

Consider the connections between MLE and MAP:
- **MLE is a special case of MAP where the prior is the uniform distribution**; a uniform prior with $\alpha=\beta=1$ assigns the same probability to every value of $\theta$ in $[0,1]$
	- In other words, a uniform prior expresses no preference for any value of $\theta$, so the estimate is determined by the data alone
- The **influence of the prior depends on how much data we have**; the pseudo-counts become negligible compared to the observed counts $N_{\text{win}}$ and $N_{\text{loss}}$ as the number of observed samples grows
- We can interpret the prior as a **regularizer** to prevent overfitting, the values of $\alpha$ and $\beta$ play a role similar to a regularization strength; the larger they are, the stronger the penalty, and thus the more data we need before the estimate moves away from the prior
## <u>Probabilistic Conditional Models</u>
Let $\mathcal{D}=\{ (x^{(1)},y^{(1)}),(x^{(2)},y^{(2)}),\dots,(x^{(n)},y^{(n)}) \}$ be observed data points where both $X$ and $Y$ are Bernoulli but **not necessarily iid**; then effectively $\mathcal{D}$ gives us a **joint probability distribution** $P(X,Y)$, from which we can **determine conditional probability distributions** using Bayes'
- Note here $Y$ is the class and $X$ is the feature

Recall Bayes' concepts regarding **conditional distributions**:
$$
\begin{align}
P(X\mid Y) &= \frac{P(X, Y)}{P(Y)}\implies P(X,Y)=P(X\mid Y)\cdot P(Y)=P(Y\mid X)\cdot P(X) \tag{Product Rule} \\
&=\frac{P(Y\mid X)\cdot P(X)}{P(Y\mid X)\cdot P(X)+P(Y\mid X^c)\cdot P(X^c)} \tag{Bayes' Theorem} 
\end{align}
$$
Recall that the event being conditioned on is **not a variable** but a constant in the conditional distribution
- The conditional distribution's type is generally determined **by the variable being described**; ie. a Bernoulli dependent on an RV of some other family is still Bernoulli
- Each conditional distribution **has its own parameters**, ie. $P(X\mid Y=0)$ and $P(X\mid Y=1)$ would have two parameters $\theta_{0}$ and $\theta_{1}$ determined by the joint distribution
	- This assumed just two binary features in each point in $\mathcal{D}$; with $d$ **binary features** we need $2^{d+1}-1$ parameters, so **number of parameters** scales **exponentially** with **number of features**
		- This is a result of the multiplicative law of conditional probability, ex. for $2$ features we would have $P(X\mid Y\mid Z)=P(X\mid Y,Z)\cdot P(Y\mid Z)\cdot P(Z)$ for which:
			- $P(Z)$ contributes $1$ parameter (note we use $Z$ here as the class and both $X$ and $Y$ as features)
			- $P(Y\mid Z)$ contributes $2$ parameters, one for both values of $Z=z$
			- $P(X\mid Y,Z)$ contributes $4$ parameters, one for each combination of $Y=y,Z=z$
		- As number of features grows we may also get **sparse data**; most combinations of the conditioning variables will have few or no examples, which is taken literally as probability of $0$ for the MLE calculation

During **learning**, the model calculates the MLEs of each parameter to fully determine the conditional distributions
- For two binary features this is as simple as counting occurrences out of the total number of data points in a table
- More formally, we use facts about the Bernoulli distribution and Bayes' to determine expressions for $P(x^{(i)},y^{(i)})=P(y{(i)})\cdot P(x^{(i)}\mid y^{(i)})$, then assume the joint events are iid and take the steps from the previous chapter about determining the likelihood and log-likelihood functions, solving for derivative $0$, etc.
- Note features do not have to be binary; for a Normal feature we can still determine MLE for parameters like mean and variance (Normal has $2$ parameters unlike Bernoulli with $1$) by simply averaging the features from the data table
	- Formally deriving this is for Chapter 8
	- Inference becomes more complicated as well since the Normal PDF is much messier than the Bernoulli PMF used in all the probability calculations

During **inference**, the model applies Bayes' Theorem to calculate $P(Y \mid X=x)$ and then evaluates $\arg\max_{y \in \text{classes}} P(Y=y \mid X=x)$ to determine its classification
- This is a **generative classifier** with a learned class prior $P(Y)$ together with learned class-conditional distributions for the features $P(X\mid Y)$
	- Examples include Bayes classifiers, Naïve Bayes, and Gaussian Discriminant Analysis
	- In contrast a **discriminative classifier** learns a mapping directly from inputs to labels by modelling only $P(Y=y\mid X=x)$, it never specifies a distribution over $X$
		- Examples include logistic regression, softmax regression, and decision trees
## <u>Naive Bayes</u>
**Bag-of-Words:** treat a piece of text as a collection of its words, **disregarding word order and occurrence frequency**
- Build a **vocabulary** of all **unique** words across the dataset, then represent each piece of text as a vector $\mathbf{x}$ of $0$s and $1$s, one entry per vocabulary word, indicating whether that word appears; then we have $D=$ number of unique words as the number of features
- Learn $P(x\mid y=0)$ and $P(x\mid y=1)$ for each word $x$ in the vocabulary, ie. what do class $0$ text features look like and what do class $1$ text features look like
	- Recall though, if our vocabulary is size $D$ then each vector will be $\mathbf{x}\in \mathbb{R}^D$ and the number of parameters will be $2^{D+1}-1$; we resolve this with the Naive Bayes' assumption
- During inference **flip the question around with Bayes’ Theorem** to classify a new review given a vector of occurrences

**Naive Bayes:** assume that the word features are **conditionally independent**
$$\begin{aligned}
P(x_1, x_2, \dots, x_D \mid y) &= P(x_1 \mid y)\,P(x_2 \mid y)\,\cdots\,P(x_D\mid y) \\
& = \prod_{j=1}^{D}P(x_j\mid y)
\end{aligned}
$$
This is not the same as saying each $x_{i}$ and $x_{k}$ are marginally independent (they generally are not); it is saying that once you already know the class, learning whether one word appears tells you nothing more about whether another word appears (which is a **strong and false assumption**, but we will use it)
- Then, each word becomes a Bernoulli RV $X_{j}$ with each conditional distribution $P(X_{j}\mid Y)$ having parameters $\theta_{j,c}$ for each $c\in \{ 0,1 \}$, for a total of $1+2D<2^{D+1}-1$ parameters or the set $\theta =\{ \theta_{Y} \}\cup\{ \theta_{j,c} \}_{j=1,c=0}^{j=D,c=1}$

During **learning**, the model calculates the MLEs of each parameter to fully determine the conditional distributions
- For small enough vocabularies and few enough classes, simply observing the occurrences of words per each class is possible

In order for inference to classify a new review $\mathbf{x}$, we will need to apply Bayes’ rule to calculate $P(y=0\mid \mathbf{x})$ and $P(y=1\mid \mathbf{x})$ and choose the greater probability:
$$
\begin{aligned}
\arg\max_{c \in \{0, 1\}} P(y = c \mid \mathbf{x}) &= \arg\max_{c \in \{0, 1\}} \frac{P(y = c) P(\mathbf{x} \mid y = c)}{P(\mathbf{x})} = \arg\max_{c \in \{0, 1\}} P(y = c) P(\mathbf{x} \mid y = c)
\end{aligned}
$$
Where we use Naive Bayes' to calculate:
$$
\begin{aligned}
P(\mathbf{x} \mid y = c) = P(x_1 \mid y =c) \, P(x_2 \mid y =c) \, \cdots \, P(x_D \mid y =c) = \prod_{j = 1}^D P(x_j \mid y = c)
\end{aligned}
$$
One large drawback to this model
- If any word $x_{j}$ in $\mathbf{x}$ is **never found** in a given class $y=a$ in the training data, then the MLE for that parameter is $\theta_{j,a}=0$ and equivalently $P(x_{j}\mid y=a)=0$ which sends the entire calculation $P(\mathbf{x} \mid y = a)=0$ if $x_{j}$ is **present** in our new input to be classified
- Similarly, if any word $x_{j}$ in $\mathbf{x}$ is **always found** in a given class $y=b$, then the MLE for that parameter is $\theta_{j,b}=1$ and equivalently $1-P(x_{j}\mid y=b)=0$ which sends the entire calculation $P(\mathbf{x} \mid y = b)=0$ if $x_{j}$ is **not present** in our new input to be classified
- The fix is to replace the hard MLE estimate with a MAP estimate using a Beta prior, which smooths every $\theta_{j,c}$ away from exact $0$s and $1$s using a priori pseudo-counts
# <u>8: Gaussian Discriminant Analysis</u>
## <u>Univariate GDA</u>
If we want a generative classifier and assume that each class-conditional distribution is a Gaussian, then we obtain a **Gaussian Discriminant Analysis** model
- Essentially, we fit a Gaussian per class from data (e.g. by maximum likelihood) then use Bayes’ Theorem to classify new points (e.g. pick the class with highest probability)

As before we assume data $\mathcal{D}=\{ (x^{(1)}, c^{(1)}), (x^{(2)}, c^{(2)}), \dots, (x^{(N)}, c^{(N)}) \}$ where each $x$ is **iid** from some Gaussian with **sample mean** $\mu$ and **sample variance** $\sigma^2$, and the class $c$ is **binary**, then by doing the standard likelihood and log-likelihood derivations of MLEs we get:
- $\mu_{\text{MLE}}=\mu$
- $\sigma^2_{\text{MLE}}=\sigma^2$

A GDA model is a generative model of the joint distribution of the feature and the class, ie. $p(x, c) = p(x \mid c)\cdot p(c)$
- The Gaussian part of GDA means that we assume that given the class, the feature is drawn from a Gaussian distribution, so for each class $k\in{0,1}$ we have $p(x \mid c = k) = \mathcal{N}(x \,;\, \mu_k, \sigma_k^2)$ where $\mathcal{N}$ is the PDF of the Gaussian conditional distribution with class-specific mean and variance $\mu_k, \sigma_k^2$
- As before, inference uses Bayes' to determine $p(c \mid x)$

For learning this binary univariate GDA, we have $5$ parameters; $\theta$ for the class distribution, and $\mu_0, \sigma_0^2$ and $\mu_1, \sigma_k^1$
- Once we have determined these parameters, we can overlay the two Gaussian distributions on one plane with $x$ on the $x$-axis and the $y$-axis as the PDF value; then we select the higher PDF at each value to be the prediction
- For inference we calculate:
$$
\begin{aligned}
& p(c=1 \mid x) = \frac{p(x \mid c=1)\,p(c=1)}{p(x \mid c=0)\,p(c=0) + p(x \mid c=1)\,p(c=1)}\propto p(x \mid c=1)\,p(c=1)
\end{aligned}
$$
- For values $\geq 0.5$ we select $c=1$, otherwise $c=0$
- The **decision boundary** is the value(s) of $x$ where the two terms in the denominator are equal, ie. where the two Gaussians (weighted by the class prior) give equal probabilities (in the binary univariate case the decision boundary is a point, since we have a single feature)
